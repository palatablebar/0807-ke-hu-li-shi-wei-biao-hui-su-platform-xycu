# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。对仍有差异的版本可填写暂缓意见。
5. 导出复核证据并保存于交接记录。

## 补录试算与发布

1. 在“补录试算与发布”面板选择补录 CSV（或补录样例），页面按交易时点重算覆盖变化并列出未解决交易。
2. 确认试算结果后决定是否新建发布版本；试算与发布同源，内容相同的重跑不会新增版本。
3. 发布前系统重算整条客户时间线：存在断档、重叠或未关联交易时版本保持待复核并列出记录键，当前已发布版本不受影响。
4. 修复来源后重新试算再发布。发布失败的版本与证据保留在版本列表中，旧版仍按原时点复现。
5. 在版本列表中打开任一版本可回看其覆盖变化，并下载发布证据用于追责。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次与发布版本。恢复时使用原 Docker Compose 数据卷。
